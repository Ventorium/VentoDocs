# POC 验证项与里程碑计划

> v1 实施范围 = P0（文件管理核心）+ P1（Office 编辑、分享、网站发布）。
> Agent 与向量检索（zvec-grep）整体推迟到 v2，其 POC 在 v2 启动时执行。

## 1. POC-1：Univer OSS 在线编辑（v1 必做，M2 前置）

**背景**：需求 §14.1 要求验证 DOCX/XLSX/PPTX 的导入、编辑、导出能力与保真度，并明确 OSS 与 Pro 的功能边界。用户已确认三格式全部目标在线编辑，以 POC 结果为门槛：验证通过的格式接入编辑器，未通过的降级为"预览 + 下载 + 提示暂不支持在线编辑"。

**执行方式**（约 0.5–1 天）：

1. 在独立 `poc/` 目录（不并入主工程）按官方 React 集成方式引入 `@univerjs/preset-sheets-*` / `preset-docs-*`（仅 OSS 包）。
2. 准备样例文件：
   - xlsx：公式、合并单元格、图表、图片、条件格式、多工作表。
   - docx：标题样式、表格、图片、脚注、目录、复杂段落。
   - pptx：多页、图片、图表、动画（预期不支持）、母版样式。
3. 验证链路：Office 文件 → 导入为 Univer 数据 → 编辑（单元格/段落/页增删改）→ 导出回 Office 文件 → 用 Office/WPS 打开检查保真度。
4. 逐一确认 OSS 包内可用的导入/导出能力（xlsx/docx/pptx 的 import/export 包是否 OSS 提供，还是 Pro 专属），记录替代方案（如仅存 Univer JSON 版本 + 导出降级为 CSV/JSON）。
5. 编辑器生命周期：初始化、销毁、保存、异常恢复、大文件内存占用（100MB+）。

**通过标准**：

- 产出格式矩阵：每格式记录 导入 ✅/❌、可编辑范围、导出 ✅/❌、保真度（无损 / 轻微丢失 / 结构性丢失）。
- xlsx 必须达到"导入 + 编辑 + 导出（可接受保真度）"，否则 M2 范围收窄到 xlsx 预览 + 降级方案。
- docx / pptx 结论记录在案，据此决定 M2 是"三格式全上"还是"xlsx 全上 + docx/pptx 预览"。
- 确认所有使用包均为 Univer OSS 许可证，不引入 Pro 包。

**产出**：`docs/poc/univer-matrix.md` + `poc/univer/` 最小验证工程。

## 2. POC-2：zvec-grep 集成（v2，本次不执行）

- A. `zg_engine` 以 git 依赖（`zvec-ai/zvec-grep`，crates.io 未发布，已确认 404）`cargo build` 成功；typed API（context/index/info/drop_index + hybrid search）可用。
- B. 增量索引：文件 upsert/删除后检索结果正确；部分失败不污染 freshness；索引状态可查询。
- C. 内容解析质量：docx/xlsx/pptx/pdf 与常见文本格式抽取正确性抽检。
- D. 并发与部署：单 `ZvecGrep` 实例多工作区共享的检索正确性、延迟、模型运行时行为（本地权重、空闲过期）。
- 备选：`zg --server` 守护进程模式（进程管理、通信协议、错误恢复、部署依赖）。
- 通过标准：A/B 必须通过；C 不达标的格式降级为仅文件名索引；据此定 `vk-search` 实现方式（进程内库 vs 守护进程）。

## 3. 里程碑与验收

| 里程碑 | 交付内容 | 验收（对应需求 §16 原则） |
|---|---|---|
| M0 | 仓库骨架、CI 检查、docker-compose（PG/Redis）、配置、全部迁移、JWT 认证、bootstrap 引导、用户管理 API、前端脚手架与全局框架（登录/导航/布局/设计 Token） | 登录 → 建目录 → 建用户全链路走通；二进制与 compose 行为一致；质量门（fmt/clippy/tsc build）通过 |
| M1 | 目录树 CRUD、文件上传/下载/预览、重命名/移动/复制、ACL（权限位 + 继承 + 权限弹窗）、文件锁定/解锁、版本历史 + 恢复、回收站（180 天/恢复冲突）、审计日志 + 管理页、文件名搜索 | 后端 8 个鉴权入口不可绕过；子目录无独立 ACL；锁定人之外不可写、管理员解锁不授写、锁持久；删除/恢复与元数据一致；版本默认开启；回收站 180 天 |
| M2 | Univer OSS 在线编辑（按 POC-1 格式矩阵）、编辑保存 = 新版本、并发冲突提示、锁定人外禁编辑 | 编辑保存形成历史版本并触发后续索引更新（v2）；锁与版本检查在服务端执行；格式能力与 POC 矩阵一致 |
| M3 | 文件分享（密码/有效期/次数/仅预览/撤销/访问审计）、目录网站发布（16 位标识持久、Host 路由、关闭立即 410、域名环境变量、未配置禁用） | 分享策略全服务端校验；仅预览分享不可下载；关闭后旧域名立即失效；标识关闭后再开启复用 |
| v2 | zvec-grep 全文/向量检索 + 索引生命周期、文档页 Agent、全应用 RAG Agent、内容搜索 UI | 检索结果按用户权限服务端过滤；Agent 读写 ≤ 当前用户权限；写回走统一 save 管线并生成版本 |

## 4. 风险登记

| 风险 | 等级 | 应对 |
|---|---|---|
| Univer OSS 缺 docx/pptx 导入导出或保真度不足 | 高 | POC-1 定案降级：预览 + 下载 + 明确提示；不阻塞 M1/M3 |
| xlsx 导出依赖 Pro 包 | 中 | 备选：Univer JSON 版本存储；导出走开源转换或"编辑存版 + 原文件下载"兜底 |
| 大文件编辑内存/性能 | 中 | 上传 500MB 上限（可配）；>50MB 编辑提示；性能项纳入 POC-1 |
| sqlx 编译期检查依赖开发库 | 低 | dev/CI 用 docker compose 起 PG；必要时降级为运行时检查 + 集成测试兜底 |
| 无真实 LDAP 环境 | 低 | 本地 docker 起 ldap 服务做导入联调；导入逻辑失败可报告到行级 |
| 发布泛域名未配置导致功能不可用 | 低 | 未配置 = 功能禁用 + UI 明确提示（设计已定） |
